# Agent Cockpit — Design Spec(照 UIUX_Design_Checklist Phase 0-5.5 產出)

> 2026-08-28。狀態:**待 owner approve(Phase 5.5 gate),approve 前不動 code**。
> 本檔取代先前零散迭代;實作以本檔為唯一來源,drift 必須回報。

## Phase 0 — 研究與目標分析

**0.2 Persona(主)**:owner,PM,雙螢幕工作(VS Code/瀏覽器全螢幕),widget 常駐右上。
- 環境:深度工作中被動瞄一眼(80%)/主動巡檢(20%)。時間:一次 3–15 秒,不是「使用一個 app」而是「瞄儀表」。
- 資訊認知順序:①有沒有事 ②哪類、多急 ③是什麼、要我做什麼 ④就地理解/行動。
- 情緒:怕漏急事的低度焦慮+對分心極度敏感——**寧可少顯示,不可誤鬧**。
- 次要 persona:會議前 5 分鐘的 owner——只要「下一場+要帶什麼」,其他全是噪音。

**0.3 起始狀態**:剛寫完一段東西抬頭;已知自己大概有哪些案子,不記得細節與時效。
**0.4 JTBD**:「10 秒內知道現在有沒有需要我的事、是什麼、多急;30 秒內理解該單全景並採取行動(回覆/驗收/開文件)。」
**0.5 常見錯誤(此類 ambient dashboard)**:
- 誤鬧疲乏:燈常亮→使用者學會忽略→真急事漏掉(最大風險)。
- 資料靜默過期:collector 死了 UI 還顯示舊資料當新資料。
- 點擊語意不一致:同長相的列,有的展開有的跳外部。
- 內部代碼外洩到 UI(P1/P6、單號、score)——使用者不用系統的語言思考。
**0.6→0.7 使用流程**(與你既有操作對齊):瞄球(哪格亮)→hover 分裂→hover 小球=面板→掃區→點列展開全景→按鈕行動→收合。

## Phase 1 — UI 種類與功能清單

**1.1 種類**:1.1.5 Dashboard(決策支援)× ambient notification 混合體。設計重點=層級清晰、可掃描、防誤鬧。
**1.2.4 三狀態(先前完全缺,本版補上)**:
| 資料區 | Loading | Empty | Error/Stale |
|---|---|---|---|
| 即時問題 | 頂列⟳旋轉,列保留舊資料 | 「沒有未讀 ✓」+模式註記 | **掃描時間>15分:標題列黃點+「資料 N 分鐘前」**;collector 連續失敗:該區「掃描失敗·點⟳重試」 |
| 會議 | 同上 | 「今天沒有會議 ✓」 | 同 stale 規則 |
| Jira | 同上 | 「沒有要你動的 ✓(開放 N 張)」 | 同 stale 規則 |
| 展開敘述 | 「敘述將於下次掃描產生」 | — | 顯示原始標題+留言 fallback |

## Phase 2 — IA(OOUX)

Entities:ChatSpace(1:N Message)/Meeting(1:1 PrepTask)/Ticket(1:N Comment;1:1 Enrichment)/Watch(1:N Ticket)/ActionItem(=Ticket 的視圖:act+need+sev)。
**漸進揭露四層**(每層只回答一個問題):
- L0 球:有沒有事?(格亮/脈動)
- L1 小球徽章:哪類、幾件?
- L2 面板列:是什麼、要我做什麼、多急?(一列=一個決策)
- L3 展開:全景敘述+對話史+行動按鈕。
導覽≤3 擊:球→面板→展開 ✓。

## Phase 3 — Tokens(已定,不再改)

四格色(owner 定)/字級 10·11·12·13·16/4px grid/圓角 4·8·12/easing 全局 `cubic-bezier(.16,1,.3,1)`/hover120·狀態200·面板320ms/tabular-nums/antialiased。

## Phase 4 — 元件與佈局(本次修正核心)

**4.A 列的統一文法(解決點擊語意不一致)**——所有面板同一結構:
```
[左緣整列熱度底色] 動作詞(11px 色字) 主句(13px/600) ......... 時效(右對齊)
                    輔句(11px dim):脈絡 · 人 · App        [hover:次要動作]
```
- **點列=展開 L3,全面板一致**(即時問題也改為展開:未讀預覽列表+「開啟聊天室↗」按鈕;不再直接跳外部——外跳一律走展開內的 ↗ 按鈕)。
- **拿掉 P1/P6 等內部代碼**:優先度只用整列底色講;動作詞用人話(回覆/驗收/會議/未讀)。
- **時效右對齊獨立欄**(tabular-nums):「等 6h」「9/24 止」「14:00」——一眼縱向掃描比對;逾期/超 24h 用 --alarm 色。
- 輔句最多 3 段(脈絡 · 人 · App),超過砍。
**4.B 會議列**:已結束的會 → 60% 降淡+動作詞改「已結束」;下一場 → 底色 sev2 起跳。
**4.C 區標**:11px/600/dim+髮絲(4.1.3)✓ 保留;fold 同款。
**4.D Stale 徽章**:面板頂「更新 HH:MM」在 >15 分時變 --hot 色+「(N 分鐘前)」。

## Phase 5 — 互動與 Guards

- 5.1 四態:列 hover=brightness1.16/active=scale .995/disabled n/a ✓;按鈕 hover 變色。
- 5.2.2 回饋:⟳=旋轉+完成時 updated 跳動;↑↓=列位移動畫 150ms;✓ 熄燈=列淡出。
- 5.2.3 Guards:⟳ debounce(掃描中 disable);展開狀態在資料更新後保留(openKeys by key)✓。
- 5.3 動畫:全局 --e ✓;球體液化=刻意例外(物理隱喻),文件化。
- 誤鬧防護(0.5#1):脈動僅 ack-新事(已看過同 sig 不再脈動)✓;**全暗=真的沒事**是神聖的,collector 失敗必須顯示 stale 而非全暗。
